# Spec 025 - Product Design & UX Pass

## Goal

Improve EMControle visual quality, navigation, usability, and overall product feel without adding new features.

## Scope

Refine:

* app visual identity
* logo/header usage
* navigation behavior
* redundant menu/actions
* illustration quality placeholders
* diary usability
* tone of interface
* web layout stability

Do not implement:

* backend
* auth
* cloud sync
* analytics
* export
* charts
* new product features

## Product Direction

The app should feel:

* trustworthy
* warm
* calm
* modern
* accessible
* supportive

Avoid feeling:

* too clinical
* too serious
* bureaucratic
* generic
* generated by AI

---

## 1. Visual Tone

### Problem

The app currently feels too serious and technical.

### Required

* Soften cards and surfaces.
* Use friendlier copy.
* Use warm orange accents.
* Improve visual hierarchy.
* Avoid hospital-like cold UI.
* Keep medical trust without becoming sterile.

Do not use excessive gradients or decorative noise.

---

## 2. Logo and Header

### Problem

Top-left text "EMControle" alone feels unfinished.

### Required

Create a compact app header component.

Use:

* app mark/logo
* EMControle text

Together as a brand.

Optional Home subtitle:

"Seu cuidado, organizado"

Do not overload the top bar.

### Usage

Use consistently on:

* Home
* History
* Diary
* Timeline
* Settings

---

## 3. Illustration Quality

### Problem

Current SVG illustrations look like placeholders.

### Required

Improve consistency:

* same stroke thickness
* same visual language
* better proportions
* cleaner body contours
* consistent orange highlights

### Application Site Illustrations

Improve:

* Avonex
* Copaxone
* generic body-region illustrations

Avoid:

* stick figures
* childish proportions
* overlapping body regions

Important:

Do not attempt photorealistic medical diagrams.

Create a professional placeholder system that can later be replaced by designer-created assets.

---

## 4. Navigation Smoothness

### Problem

Navigation on Web feels like page refreshes.

### Required

Review navigation architecture.

Prefer:

* ShellRoute
* StatefulShellRoute
* stable scaffold
* persistent bottom navigation

Avoid:

* full page rebuilds
* unnecessary route replacement
* header flicker
* scroll resets when avoidable

### Acceptance

Switching tabs should feel app-like, not website-like.

---

## 5. Redundant Navigation

### Problem

Some screens contain buttons that duplicate bottom navigation.

### Required

Remove navigation actions that already exist in bottom navigation.

Keep only contextual actions.

### Keep

* Registrar aplicação
* Nova anotação
* Editar tratamento
* Configurar tratamento

### Remove

Generic navigation buttons to screens already available in bottom navigation.

---

## 6. Main Navigation

Preferred bottom navigation:

* Início
* Histórico
* Diário
* Linha do tempo
* Ajustes

Treatment access:

* Home card
* Settings

Do not duplicate Treatment as a primary navigation destination.

---

## 7. Home UX

Home must answer immediately:

* Qual é meu tratamento?
* Quando é o próximo uso?
* Onde devo aplicar?
* Posso registrar agora?
* Qual foi o último registro?

Reduce distractions.

Prioritize actionability.

---

## 8. Portuguese Copy Review

Review labels and messages.

Prefer warmer language.

Examples:

Instead of:

* Nenhum evento registrado

Prefer:

* Nada registrado ainda

Instead of:

* Configurar tratamento

Prefer where appropriate:

* Começar acompanhamento

Keep tone respectful and adult.

---

## 9. Diary Rating Simplification

### Problem

Diary currently mixes sliders, dropdowns and emoji controls.

This creates inconsistency.

### Required

Use emoji-based selection for ALL symptom ratings.

Remove:

* numeric dropdowns
* sliders
* numeric selectors

### Fatigue

😄 Nenhuma

🙂 Leve

😐 Moderada

😣 Alta

😫 Extrema

### Pain

😄 Nenhuma

🙂 Leve

😐 Moderada

😣 Forte

😫 Muito forte

### Mood

😞 Ruim

😐 Regular

🙂 Bom

😄 Ótimo

### Sleep

😴 Ruim

😐 Regular

🙂 Bom

😄 Ótimo

### Persistence

Persist numeric values internally.

Examples:

* 1
* 2
* 3
* 4
* 5

UI must display emojis.

### Timeline

Timeline should show emojis when available.

Example:

Fadiga 😣

Dor 🙂

Humor 😄

Instead of raw numeric values.

### Acceptance

* No dropdowns remain.
* No sliders remain.
* All diary ratings use emojis.
* Timeline displays emoji indicators.
* Diary can be completed quickly with one hand.

---

## 10. Overall Consistency

Review:

* spacing
* typography
* card hierarchy
* button prominence
* empty states
* icon usage
* accessibility

The app should feel cohesive and intentional.

---

## Acceptance Criteria

* App feels more polished.
* Header uses logo + EMControle branding.
* Navigation is smoother.
* Redundant navigation is removed.
* Diary uses only emoji-based ratings.
* Timeline displays emoji indicators.
* Application site illustrations are more consistent.
* Home is clearer and less cluttered.
* No new product features are added.
* `flutter analyze` passes.
* `flutter test` passes.
